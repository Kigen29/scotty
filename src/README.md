# Frontend

React 18 + Vite + TypeScript. Tailwind for styling, shadcn/ui for primitives,
Supabase JS for data. Ten screens behind auth.

```
src/
  pages/              one component per route
  components/         shared UI
    ui/               shadcn primitives — vendored, do not hand-edit
    pipeline/         Kanban card + column
    settings/         ICP profile card, team settings
  hooks/              useAuth, useTeam, useNotifications, useRealtimeSubscription
  integrations/
    supabase/         generated client + types — do not hand-edit
  lib/utils.ts        cn() class merger
  test/               vitest setup
  index.css           design tokens as CSS variables
```

## Routes

Defined in [`App.tsx`](App.tsx). Everything except `/auth` sits inside
`ProtectedRoute` → `AppLayout`.

| Path | Screen | Does |
| --- | --- | --- |
| `/auth` | `Auth` | Sign in / sign up |
| `/` | `Dashboard` | Stats, agent health, hot leads, quota, manual outreach trigger |
| `/discovery` | `LeadDiscovery` | Lead table, manual discovery, bulk verify/enrich |
| `/campaigns` | `Campaigns` | Drafted and sent messages |
| `/sequences` | `Sequences` | Multi-step cadence authoring and enrollments |
| `/pipeline` | `Pipeline` | Drag-and-drop Kanban by lead status |
| `/conversations` | `Conversations` | Threads per lead, reply composer |
| `/reports` | `Reports` | Charts over leads and campaigns |
| `/deliverability` | `Deliverability` | Open, bounce, reply rates |
| `/settings` | `SettingsPage` | Identity, ICP, targeting, sending policy, pipeline choice |

## Design tokens

Colours live as HSL CSS variables in [`index.css`](index.css) and are mapped to
Tailwind names in [`tailwind.config.ts`](../tailwind.config.ts). Primary is
`hsl(152 60% 42%)` — a green — with a separate `--sidebar-*` set.

Use the token, never a raw colour: `bg-primary`, not `bg-[#2BAB6F]`. Both light
and dark are defined; `next-themes` toggles the `class` attribute.

## Conventions

**Styling.** Tailwind utilities, composed with `cn()` from `lib/utils`. Reach for
a shadcn primitive before writing a new component.

**Data.** Every screen currently hand-rolls `useState` + `useEffect` +
`useCallback` fetches against `supabase.from(...)`, typed as `any`. This is the
main piece of frontend debt:

- `@tanstack/react-query` is installed and `QueryClientProvider` is mounted in
  `App.tsx`, but **`useQuery` appears nowhere.** Adopting it, behind a
  `src/data/` layer of typed hooks, is Phase 4 of the architecture plan.
- Until then, follow the existing pattern rather than introducing a third one,
  and prefer `Tables<"leads">` from the generated types over `any` in new code.
  The lint budget counts every `any` you add.

**Realtime.** `useRealtimeSubscription(table, userId, onChange)` subscribes to
Postgres changes. It currently refetches the whole screen on any event — fine at
this scale, and the thing react-query adoption fixes properly.

**Generated files — never hand-edit.** `integrations/supabase/types.ts` comes
from the Supabase CLI; `previewAuthStorage.ts` is generated by Lovable and says
so at the top. Both are excluded from lint and coverage.

## Large files worth splitting

`Sequences.tsx` is 1,218 lines and `LeadDiscovery.tsx` is 764. Both mix data
fetching, dialogs, tables and forms in one component. Splitting them is Phase 4;
don't grow them further.

## Local development

```sh
npm run dev     # http://localhost:8080
```

`.env` points at the **hosted** Supabase project, so a local dev server is a
frontend onto live production data. Run `supabase start` if you want an isolated
database.

## Tests

`src/test/setup.ts` pulls in `@testing-library/jest-dom` and stubs
`window.matchMedia` (several shadcn components need it).

The suite is one placeholder assertion; coverage is 0%. See
[CONTRIBUTING.md](../CONTRIBUTING.md#tests) for where to start.
